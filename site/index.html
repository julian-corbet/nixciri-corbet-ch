nixniri

niri's own config file — generated, not hand-edited.

A home-manager module that turns structured Nix options into a real ~/.config/niri/config.kdl: input devices, layout, workspaces, column widths, keybinds (add, override, or remove any one of them), idle/lock timing, and startup. No hand-maintained KDL block, and no drift between two machines that are supposed to run the identical session.

Status: pre-alpha, real code moving to a new address

✓

Not new code — a new home for existing code

Every option on this page is the same module that has been generating a real ~/.config/niri/config.kdl as nixdesktop's own home/niri.nix: the keybind attrset with its add/override/remove semantics, the per-workspace binds generated from workspaceCount, the idle/lock command assembly. It's moving out of nixdesktop, not being written from a blank file.

!

What the move hasn't proven yet

All of that was written, revised, and fixed while living inside nixdesktop's own flake. It has not yet been evaluated as this repo's own standalone flake output, on a config that imports nixniri without also pulling in nixdesktop. nixdesktop itself hasn't been cut over to import this repo instead of its own copy yet either — that migration is separate, tracked work, not something this page's existence implies is finished.

!

No test suite

Real, working, hand-verified inside its previous home — not covered by an automated suite yet, here or there. The binds override/remove semantics in particular are exercised by hand, not by a regression test.

What it generates

Keybinds: add, override, remove

niri.binds is an attrset keyed by the exact niri key-combo string. Define a new key to add a bind, redefine a shipped key to override it (whole value — action, title, and flags together), or redefine it as null to remove it outright. Every bind niri's own upstream example config ships (Mod+arrows, Mod+1-9, the standard media keys) lives here as a real, individually overridable default.

Workspaces & column widths

workspaceCount generates that many named, always -present workspaces; presetColumnWidths controls what Mod+R cycles through. Niri's own thirds/half/two-thirds default, or your own list.

Idle & lock, computed — not spawned

idle.lockAfterSeconds / idle.suspendAfterSeconds assemble a read-only idle.command: the full swayidle invocation, ready to hand to a systemd user service. Not spawned by this module itself — niri has no way to restart a spawn-at-startup line when a running session's config changes, so a real idle daemon needs to be a service, not a startup line. See "The cross-repo contract" below.

Escape hatches, not a wall

extraStartup, extraWindowRules, extraBinds, and extraTopLevel accept raw KDL, verbatim, for anything the structured options don't model yet. Structure for the common case; an escape hatch for everything else.

Installs nothing

This module never names a package or an absolute binary path — not for niri itself, not for terminal/launcher/lockCommand/osd. Package names and binary paths aren't portable (thunar on Arch is xfce.thunar in nixpkgs); resolving them is a platform backend's job — nixarch for Arch/CachyOS, or plain NixOS environment.systemPackages.

Compositor-neutral policy stays upstream

nixdesktop keeps the platform-neutral role policy (which desktop roles a session wants filled) and the compositor-agnostic chrome — waybar, mako, swaylock, nwg-bar, eww, the idle/lock systemd service. This repo owns exactly one thing: niri's own config file.

Get started

1. Add the flake input

inputs.nixniri.url = "github:julian-corbet/nixniri-corbet-ch";

2. Import and configure

imports = [ inputs.nixniri.homeManagerModules.niri ];

nixniri.niri = {
  enable = true;
  terminal = "kitty";
  binds."Mod+T".hotkeyOverlayTitle = "Open a Terminal";
  binds."Print" = null; # remove the shipped screenshot bind
};

3. Renamed from nixdesktop — no shim

The option namespace moved from nixdesktop.niri.* to nixniri.niri.*, matching this family's own convention (the top-level attribute is always the repo's own name). Migrating from nixdesktop's old copy means renaming every reference, including inside binds/extraStartup overrides. No compatibility alias exists at this stage.

Where this fits

1. Compositor config — nixniri / nixscroll

Generates the compositor's own config file. Nothing else. Doesn't know or care what bar you run, what notification daemon you have, or what a "role" is.

2. Policy + shared chrome — nixdesktop

Which roles a session wants filled (file manager, polkit agent, notification daemon, bar), plus the compositor-agnostic pieces: waybar, mako, swaylock, nwg-bar, eww, and the idle/lock systemd service. Imports whichever compositor layer(s) a machine actually uses.

3. The hub

An actual machine's own config, importing nixdesktop plus exactly one compositor layer, resolved into real installed packages by a platform backend such as nixarch.

The cross-repo contract: idle.command

The one real API surface the split creates. Neither repo wires the idle daemon together implicitly anymore — that was only true when both lived in one file. The consumer connects them explicitly: 

imports = [
  inputs.nixniri.homeManagerModules.niri
  inputs.nixdesktop.homeManagerModules.session
];

nixniri.niri = {
  enable = true;
  idle.lockAfterSeconds = 300;
  idle.suspendAfterSeconds = 600;
  lockCommand = "swaylock";
};

nixdesktop.session.idleAndLock = {
  enable = true;
  # nixniri assembles the command; nixdesktop's session layer runs it.
  command = config.nixniri.niri.idle.command;
};

A consumer who only wants niri's own config file — no bar, no notification daemon, no systemd session layer — imports nixniri.homeManagerModules.niri alone and ignores idle.command entirely; the lockCommand-bound keybind still works without an idle daemon running.

Roadmap (planned, not yet built)

Cut nixdesktop over

nixdesktop's own flake.nix still exports its original home/niri.nix directly. Pointing it at this repo instead — and deleting its own copy — is separate, tracked work this page's existence doesn't imply is finished.

A NixOS-module mirror

For parity with how sibling projects export both layers, if a system-level piece of this ever turns out to be needed — nothing here currently requires root.

Integration tests

Exercising the binds add/override/remove semantics and the idle.command assembly directly, not just eval-time type checks.

Standalone evaluation, proven

A real build of a config that imports only nixniri — no nixdesktop alongside it — to confirm the split actually holds and not just typechecks.
